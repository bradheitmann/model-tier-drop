## 1. Purpose, strategy, architecture

- **Purpose.** Pick the cheapest model tier that fits a task, escalate one step at a time on failure, and record every decision. The tier ladder is `system_one`, `specialised`, `cheap_generalist`, `frontier`, `tailored` (README.md; plan/requirements.md R-01…R-07).
- **Architecture and concern ownership.**
  - `crates/core`: the pure engine. It plans and records; it never calls a model and never touches the filesystem, the clock or the network (AGENTS.md; guarantee G1).
  - `crates/cli`: the `tier-drop` CLI with a JSONL ledger. It also holds the model-atlas export mapping (`crates/cli/src/atlas.rs`).
  - `crates/worker`: the hosted MCP server, a workers-rs Cloudflare Worker that refuses unknown fields. Live at `https://model-tier-drop-mcp.bradheitmann.ai`, deployed 2026-10-19 (S-06).
  - `skill/`: the agent skill, also served by the Worker.
  - `adapters/dsh`: a strict-TypeScript dsh plugin.
  - `registry/registry.example.json`: example configuration. Its values are not measurements; model names are configuration, never code.
- **Strategy.** Contracts in `plan/` change before code. Every slice runs a predeclared DONE list, a freeze, independent QA by a different model family, and charter acceptance before it reaches main (AGENTS.md "Landing a slice here").
- **Roadmap and why it is ordered.** S-11 (deploy) must precede merging s10/s14, because the live Worker refuses the new `lineage` field (plan/contracts.md S-11). atlas_ref needs that field live. A first version worth pinning comes after deploy + merge.
- **Accepted decisions** live in `plan/amendments/` (2026-10-31 adjacent escalation; 2026-11-01 atlas export customer; 2026-11-05 registry version 2) and `charter/owner-decisions/` (2026-11-04 semantic attestation key).
- **Rejected alternatives** (recorded where they were decided):
  - effort `low` for Qwen: falsified, it fills the output cap (reveng ROUND8 report);
  - prompt reordering ("ask-first"): no gain, and it broke 1 of 2 runs (ROUND18);
  - committed versioned schemas built now: deferred, no consumer yet (STATE, polyswarm R16);
  - relying on `planctl lint --json` as a plan check: it only checks that a file is one JSON object.
