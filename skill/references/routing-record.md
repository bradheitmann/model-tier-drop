# Routing record

Every routed task ends with one `RoutingDecision` appended to `<ledger_dir>/decisions.jsonl` by `tier-drop decide` (or returned by the MCP tool `decide`, which stores nothing). It answers four questions: which tiers were tried, why each lower tier was disqualified or skipped, which candidate won, and on what evidence.

Print its JSON Schema with `tier-drop schemas routing_decision`.

## Fields

| Field | Type | Meaning |
|---|---|---|
| `schema_version` | string | Record format version, carried by every ledger record. |
| `decision_id` | string | Id of this decision. Generated by `tier-drop` when absent. |
| `task_id` | string | The task this decision routes. Matches a line in `tasks.jsonl`. |
| `family` | string | The task's activity. Disqualifications are matched on it. |
| `ladder` | array of `Tier` | The tier order used for this task, from `ladder(task)`. |
| `tiers` | array | One entry per ladder tier, in ladder order (below). |
| `winner` | object or null | The chosen candidate and its evidence (below). Null when every tier was disqualified or skipped. |
| `ranking` | array | Every qualified attempt in the winning tier, best first (below). |
| `review` | `"strict"` or `{ "sampled": { "class", "decision_ref" } }` | The task's review profile, copied from the task. |
| `policy_sha256` | string | SHA-256 of the canonical policy used, so the decision can be reproduced. |
| `decided_at` | RFC 3339 UTC timestamp | When the decision was made. |
| `record_sha256` | string | SHA-256 of the canonical JSON of this record without this field. |

### `tiers[]`

| Field | Meaning |
|---|---|
| `tier` | The `Tier` value. |
| `status` | `disqualified`: an in-force disqualification exists for the family and tier. `skipped`: a structural reason applied. `tried`: attempts exist but the tier neither won nor is disqualified. `selected`: the winner came from this tier. |
| `refs` | Ids that justify the status: disqualification ids for `disqualified`, attempt ids for `tried` and `selected`. |
| `detail` | One sentence: the skip reason and detail, or the disqualification reason. |

Tiers after the selected one normally carry no attempts; that is expected, because the rule forbids trying a higher tier once a lower tier qualifies.

### `winner`

| Field | Meaning |
|---|---|
| `candidate` | The `Candidate` that won: `single`, `panel`, `cascade` or `draft` (see `references/composition.md`). |
| `attempt_id` | The attempt whose output is the task's result. |
| `floor_result` | The `FloorResult` of that attempt: `attempt_id`, `passed` (always true for a winner), `failures` (empty for a winner). |
| `score.quality` | Mean of the attempt's metrics named in `policy.required_floors`. |
| `score.cost_usd` | The attempt's cost per task. |
| `score.latency_ms` | The attempt's latency. |

### `ranking[]`

Each entry has `candidate`, `attempt_id`, `quality`, `cost_usd`, `latency_ms`. Only attempts with `outcome: "answered"` whose `FloorResult` passed are ranked.

The ranking rule (the band rule):

1. Sort by `quality`, highest first.
2. Candidates whose quality is within `policy.quality_band` (absolute, default 0.02) of the best form the top band. Inside it, order by `cost_usd`, cheapest first.
3. Candidates whose cost is within `policy.cost_band` (relative, default 0.10) of the cheapest in the band are ordered by `latency_ms`, fastest first.

The winner is the first entry of the ranking in the lowest ladder tier that has a qualified attempt. A cheaper higher-tier attempt never beats a qualified lower-tier one, and an attempt below a floor never outranks one that clears it.

## Related records the decision points to

`Attempt` (in `attempts.jsonl`): `attempt_id`, `task_id`, `family`, `tier`, `candidate`, `outcome`, `metrics`, `judge` (`kind`, `ref`), `cost_usd`, `latency_ms`, `tokens` (`input`, `output`), `input_sha256`, `output_sha256`, `rights`, `eval_item_id`, `recorded_at`, `record_sha256`.

`Disqualification` (in `disqualifications.jsonl`): `disqualification_id`, `family`, `tier`, `reason`, `evidence` (attempt ids or eval run ids), `detail`, `registry_as_of`, `decided_at`, `expires_at`, `record_sha256`.

## Reading a decision

To answer "why did this task run on that model": open the decision, read `tiers` from the top, follow each `refs` id into `disqualifications.jsonl` or `attempts.jsonl`, then read `winner.floor_result` and the first lines of `ranking`. To check that nothing was altered, run `tier-drop ledger verify --ledger DIR`; it recomputes every `record_sha256` and names any `file:line` that does not match.

Never edit or append a decision by hand. If a decision was made on a wrong registry or policy, fix the input and run `tier-drop decide` again; the ledger keeps both lines, and the later `decided_at` is the current one.
